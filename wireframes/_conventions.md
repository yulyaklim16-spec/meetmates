# Конвенции вайрфреймов MeetMates

> На эти правила опирается каждая страница в `wireframes/`. Что рисуем — в
> [`_screens.md`](./_screens.md); откуда взяты экраны и состояния — [`../sitemap.md`](../sitemap.md).
> Правила продукта не переписываются здесь: конвенции говорят **как рисовать**,
> бриф [`../CLAUDE.md`](../CLAUDE.md) — **что**.

---

## 1. Детализация: структура, иерархия, зоны

Вайрфрейм доказывает, что **флоу работает и экран не тупик**, — до того как в него
вложат визуал. Поэтому на странице есть только три вещи: **из чего состоит экран**,
**что здесь главное** и **где проходят границы зон**.

| Есть на вайрфрейме | Нет до концепта |
|---|---|
| Блоки, их порядок и вложенность | Цвет, кроме серого |
| Размер и вес как признак иерархии | Гарнитура: только системный стек по умолчанию |
| Границы зон: шапка, лента, действие, таб-бар | Тени, скругления сверх минимальных, градиенты |
| Плашка-заполнитель на месте фото, с подписью | Иконки, иллюстрации, логотип |
| Реальный текст (раздел 3) | Реальные фотографии |
| Рабочие ссылки между страницами | Анимация и переходы |

**Серый ничего не кодирует.** Нельзя «красный — ошибка», нельзя «зелёный — успех»:
на вайрфрейме состояние объясняется **текстом**, а не оттенком. Если состояние
непонятно в сером — оно непонятно и в цвете, просто это видно позже и дороже.

**Палитра — четыре значения серого и два текстовых**, в `_wire.css`:

| Токен | Значение | Где |
|---|---|---|
| `--w-surface` | `#ffffff` | Фон страницы и карточек |
| `--w-zone` | `#ededed` | Плашка-заполнитель: фото, аватар, карта |
| `--w-line` | `#d6d6d6` | Границы и разделители |
| `--w-fill` | `#f6f6f6` | Второстепенная зона: sheet, поле ввода |
| `--w-ink` | `#1a1a1a` | Основной текст |
| `--w-ink-2` | `#555555` | Вторичный текст, подписи (7,4:1 — читается) |

**Отступы, радиусы и тач-таргеты берутся из токенов проекта** — `--s-*`, `--r-sm`,
`--tap-min`, `--screen-max` из [`../tokens/tokens.css`](../tokens/tokens.css)
(Рабочие соглашения, п. 2). Цвета из токенов **не подключаются**: их очередь —
на этапе концепта. Так шкала отступов доживает до UI без пересчёта, а палитра
не протекает в серые макеты.

## 2. Разметка: семантический HTML

Каждая страница — самостоятельный `.html` без сборки: открывается двойным щелчком.
Общие стили — один файл `_wire.css`, подключается относительной ссылкой.

**Сплошные `div` — ошибка этапа.** Структура экрана и есть предмет вайрфрейма, а она
выражается тегами:

| Что на экране | Чем размечается |
|---|---|
| Шапка экрана: заголовок, кнопка назад, `⋯` | `<header>` |
| Нижний таб-бар `People · Plans · Chats` | `<nav aria-label="Основная навигация">` |
| Содержимое экрана | `<main>` |
| Смысловой блок со своим заголовком | `<section>` + `<h2>` |
| Карточка человека, карточка запроса, сообщение, отклик | `<article>` |
| Фильтры, создание запроса, поле ввода в чате, верификация | `<form>`, `<fieldset>` + `<legend>`, `<label for>` |
| Любое действие | `<button type="button">`, не `<div onclick>` и не `<a>` без адреса |
| Переход на другой экран или состояние | `<a href>` |
| Список чего угодно однородного | `<ul>` / `<ol>` + `<li>` |
| Дата и время встречи | `<time datetime="…">` |
| Зона фото с подписью | `<figure>` + `<figcaption>` |
| Совпадение — модальный момент | `<dialog open>` |
| Счётчик `2 going · 1 spot left` | `<output>` |

**Заголовки идут по порядку**: один `<h1>` на страницу, дальше `h2`, `h3` без пропусков.
На разборе раздела 3 пропуск уровня оказался реальным дефектом — на вайрфреймах он
ловится бесплатно.

**Доступность проверяется уже здесь**, потому что потом дороже: у каждого поля есть
`<label>`, у каждой кнопки — текст (не только символ), фокус виден, тач-таргет ≥ 44px
(`--tap-min`), контраст серого текста ≥ 4,5:1 (§8 брифа).

## 3. Текст: настоящий, из нашего домена

**Lorem ipsum запрещён.** Заглушка прячет главный риск этапа: что текст не помещается,
что кнопка называется непонятно, что в пустом состоянии нечего сказать. На вайрфрейме
стоит тот текст, который поедет в прототип.

**Копирайт интерфейса — на английском** (Рабочие соглашения, п. 1). Русский — только
в комментариях `<!-- -->` и в подписях к зонам-заполнителям.

| Объект | Что пишем |
|---|---|
| Карточка в колоде | `3 common interests` · `Hiking, Board games, Coffee` · `Dasha, 27` · `Verified` · `Regular` · `6 meetups attended` · `Replies quickly` · `~2 km away` |
| Профиль другого человека | `Photo 2 of 4` · `About` · `Interests` · `Upcoming plans` · `Report` · `Block` |
| Запрос на компанию | `Go for a walk on the embankment?` · `Sat, 14 Jun · 18:00` · `No date yet` · `Podil` · `+1 · 1 spot left` · `2 going · 1 spot left` · `Who can join: women only` · `Ask to join` |
| Диалог | `Say hi` · `Suggest a day` · `Invite together` · `Still going?` · `Yes` · `Can't make it` |
| Верификация | `Verify to start chatting` · `Face partly out of frame — try again` · `Sent to a human reviewer` |
| Пустые состояния | `You are all caught up` · `No plans nearby yet` · `Reset filters` · `See plans nearby` |

**Три запрета копирайта действуют и на вайрфреймах** — текст настоящий, значит и правила
настоящие:

- дейтинг-лексика запрещена: `mates`, `hang out`, `join`, `plans` — да; `date`, `singles`,
  `hookup` — нет (п. 6);
- об одиночестве не пишем: `lonely`, `alone`, `no friends` — нет (п. 13, `D-20`);
- о составе компании можно, об искомом человеке — нельзя: `Who can join: women only` — да,
  `Looking for a girl` — нет (`D-25`).

**Имена и цифры — из мок-данных §12 брифа:** ~20 профилей, ~12 запросов, один город,
большинство на `+1`, один-два с `Women only`. Один и тот же человек называется одинаково
на всех страницах: если в колоде `Dasha, 27`, то и в чате `Dasha`.

## 4. Файлы и состояния

**Одна страница — одно состояние.** Структура у всех страниц экрана одинаковая, меняется
содержимое: так на глаз видно, что состояние — это тот же экран, а не другой.

```
wireframes/<screen>.html              базовый — рабочий вид экрана
wireframes/<screen>-empty.html        пусто
wireframes/<screen>-error.html        ошибка
wireframes/<screen>-loading.html      загрузка
wireframes/<screen>-waiting.html      ожидание чужого решения  D-42
wireframes/<screen>-success.html      только если «получилось» — не рабочий вид
```

Имена — латиницей, строчными, без пробелов: `deck.html`, `deck-empty.html`,
`plan-waiting.html`. Имя экрана берётся из таблицы в [`_screens.md`](./_screens.md)
и больше не меняется.

**Базовая страница — рабочий вид, ради которого экран существует:** заполненная колода,
открытая карточка запроса, идущий разговор.

**Про `-success`.** У большинства экранов успех и есть базовый вид, отдельной страницы
не нужно. Она появляется там, где продукт даёт **отдельное «получилось»**, не совпадающее
с рабочим видом: верификация пройдена, пара подтверждена, день принят. Так это и отмечено
в таблице состояний `_screens.md` — успех стоит не везде.

**Про `-waiting`.** Пятый класс состояний `D-42`: человек ждёт не данные, а другого
человека — днями. Страница обязана называть три вещи: **кто должен ответить**, **сколько
это живёт**, **что можно сделать вместо ожидания**. Спиннер здесь запрещён — он врёт,
что тормозит приложение.

**Каждая страница состояния — не тупик** (п. 10): с пустого, ошибочного и ждущего вида
всегда есть выход, и он нарисован кнопкой или ссылкой, а не подразумевается.

**Панель навигации — на каждой странице.** Слева от мокапа стоит дерево всех макетов:
**раздел → экран → состояния**, с отступами по вложенности. Разделы — ветки дерева
экранов из [`../sitemap.md`](../sitemap.md), экраны и состояния — из
[`_screens.md`](./_screens.md); руками там ничего не пишется. Текущая страница отмечена
`aria-current="page"` и не является ссылкой. Панель служебная и на прототип не едет,
поэтому стоит **снаружи** мокапа.

Панель вставляется скриптом между метками — новая страница обязана их содержать:

```html
<body>
<!-- nav:start -->
<!-- nav:end -->
```

**Страницы существуют все, даже ненарисованные.** Всё, что перечислено в таблице
состояний, имеет файл: где макета ещё нет, лежит **заглушка** — тот же мокап, пустой
экран, надпись `Макет не нарисован` и метка `<!-- stub -->` в начале файла. Так из панели
можно перейти куда угодно, а не упереться в 404, и видно, сколько осталось. Заглушки
создаёт тот же скрипт; рисовать поверх — значит заменить содержимое `main.app`
и убрать метку `<!-- stub -->`.

**Одна команда на всё:** `node scripts/build-wireframes.mjs` — создаёт недостающие
заглушки, обновляет панель во всех страницах и пересобирает раздел 4 сайта. Раздел
считает заглушки отдельно от нарисованного, поэтому «1 из 34» остаётся правдой.

## 5. Формат страницы: мокап телефона обязателен

**Каждая страница рисуется внутри мокапа телефона** — все без исключения. Мы строим
**мобильный веб** (§3), и продукт не владеет экраном целиком: сверху системная строка,
снизу панель браузера и индикатор жеста. Макет без рамки врёт про высоту, и враньё
обнаруживается на телефоне, когда переделывать дорого.

| Зона | Высота | Чья |
|---|---|---|
| Системная строка (часы, связь) | 47px | iOS |
| **Продукту принадлежит** | **713px** | **наша** |
| Панель браузера с адресом | 50px | браузер; в Safari iOS она **снизу**, а не сверху |
| Индикатор жеста | 34px | iOS |
| Экран целиком | 844px | — |

**Скелет страницы** — копируется как есть:

```html
<body>
<div class="device">
 <div class="screen">
  <p class="statusbar"><span>09:41</span><span>Wi-Fi · 100%</span></p>

  <header>…</header>
  <main class="app">…</main>
  <nav aria-label="Основная навигация">…</nav>

  <p class="fold"><span>сгиб — ниже не наше</span></p>
  <p class="browserbar">meetmates.app</p>
  <p class="homebar" aria-hidden="true"></p>
 </div>
</div>
<footer class="meta">…служебное, под мокапом…</footer>
</body>
```

**Правила мокапа.**

- `div.device` и `div.screen` — **единственные разрешённые `div`** в наборе: у корпуса
  и экрана нет семантики, это устройство, а не содержимое. Раздел 2 действует внутри.
- Экран **фиксирован 844px**. Если содержимое не помещается в 713 — это **находка,
  а не повод растянуть рамку**: лишнее вылезает за экран, и на макете видно, сколько
  именно не влезло.
- Системные зоны **не стилизуются под наш UI**: они серые, подписаны и ничего не делают.
  Ничего не рисуем под индикатором жеста и за системной строкой.
- **Сгиб** — верхняя граница панели браузера; её рисует рамка самой панели, `p.fold`
  даёт только подпись. Что ниже — не наше и по скроллу не достаётся.
- Служебный блок и подписи зон стоят **снаружи** мокапа: внутри они врут про высоту.
- Прочее: `<title>` — `<Экран> · <состояние> · MeetMates wireframe`; в `<head>` —
  комментарий с кодом экрана из `sitemap.md` (`II.1`), его job и местом в потоке.

**Что мокап уже показал.** Наш таб-бар оказывается вплотную над панелью браузера Safari —
две панели подряд у нижнего края. На концепте проверить, не читаются ли они как одна;
если да, решение принимается там, а не здесь.

## 6. Что оставляем на потом

| Откладываем | Куда |
|---|---|
| Цвет, градиент, палитра | Концепт → `tokens/` |
| Гарнитура, типографическая шкала | Концепт |
| Тени, глубина, скругления сверх минимальных | Концепт |
| Иконки, логотип, иллюстрации | Концепт |
| Реальные фотографии | Концепт (в прототипе — плейсхолдеры, §12) |
| Свайп-физика, анимация, `prefers-reduced-motion` | Прототип |
| Готовые UI-компоненты и их состояния | `components/` |
| Десктопная раскладка | После прототипа |

**Чего не откладываем, хотя хочется:** пустые состояния, тексты кнопок, порядок чтения
карточки (`D-13`), доступ к `Report / Block` там, где виден другой человек (п. 4),
и выход из каждого пустого экрана (п. 10). Это структура, а не оформление.

## 7. Страница готова, если

1. Открывается файлом, без сборки; стили — только из `_wire.css` и шкал `tokens.css`.
2. Экран стоит **в мокапе телефона** по скелету раздела 5; системные зоны на месте,
   продукт живёт в своих 713px.
3. Ни одного `div`, кроме `device` и `screen`; заголовки без пропусков уровней.
4. Весь текст — настоящий, английский, проходит три запрета копирайта.
5. Состояние понятно **без цвета** — из текста и структуры.
6. С экрана есть выход: в пустом, ошибочном и ждущем виде нарисована кнопка или ссылка.
7. Если на экране виден другой человек — есть `Report` и `Block`.
8. Тач-таргеты ≥ 44px, у полей есть `<label>`, фокус виден.
9. В `<head>` записано, какой это экран по `sitemap.md` и какой job он решает.
