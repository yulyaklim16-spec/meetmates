## Сущности

**Правило отбора.** Сущность попадает в основной список, только если её требует
хотя бы один job из `jtbd.md`. Всё, что есть в брифе, но ни одним job не порождается, —
в разделе «Под вопросом» ниже, а не здесь. `[?]` — объект предполагается, а не выведен.

**Как читать связи:** `→` «состоит из / порождает», `←` «принадлежит / ссылается на».

### Карта связей

```
Человек ──────────── лайк ──→ Совпадение ──→ Чат 1:1
   │                                            
   ├─ автор ─→ Запрос ──→ Отклик ──→ (подтверждён) ──→ Чат запроса
   │              │                                        │
   │              ├─ повтор ─→ Серия ──────────────────────┤
   │              │                                        │
   │              └─ дата назначена ─→ Встреча ←───────────┘
   │                                     ├─→ Подтверждение явки (Still going?)
   │                                     ├─→ Подтверждение присутствия (Who made it?)
   │                                     └─→ Ссылка близкому
   │
   ├─→ Верификация · Ступень · Отзывчивость · Счётчик встреч  (сигналы доверия)
   └─→ Жалоба / Блокировка
```

### 1. Человек (профиль)

**Порождает:** M1 «не с кем» — нужен второй человек; R1 «нашла человека с общими интересами»;
R2 «видела его только на фотографиях»; S1 «чтобы во мне видели человека, которому можно
доверять»; G1 «за несколько секунд понять».

| Часть | Поля | Из какого job |
|---|---|---|
| Идентификация | имя, возраст, город | R1, G1 |
| Фото | 2–6, одно главное | R2 («видела только на фотографиях») |
| Интересы | 3+ тега из каталога | R1 («общие интересы»), G3 |
| Био | до ~150 символов | G1 |
| Пол | опционально; нужен только для ограничения отклика на своём запросе | R2 (через ограничение «кто может откликнуться») |
| Интент | чипы «зачем ты здесь» | **ни одного job** → см. «Под вопросом» |
| **Сигналы доверия** | Verified · ступень · счётчик подтверждённых встреч · отзывчивость | R2, S1, G1 |
| Предпочтения | возрастной диапазон, радиус, кого ищу | — служебные, job не порождает `[?]` |

**Связи:** → свои запросы · → отклики · → совпадения · → чаты · → подтверждённые встречи
(счётчик) · → верификация · → жалобы и блокировки (в обе стороны).

**Чего в профиле нет по job:** оценок от других людей (S1 — «выглядеть тем, кому можно
доверять», а не «быть оценённым»), присутствия «онлайн».

### 2. Запрос на компанию

**Порождает:** M1 «у моих планов была компания»; R1 «перейти от совпадения к встрече, минуя
разговор» — первое сообщение и есть приглашение на план; G2 «хочу куда-то пойти, а компании
нет»; G3 «занятие есть, компании нет»; R5, S2 — со стороны автора.

| Поле | Обязательность | Из какого job |
|---|---|---|
| **Занятие** — что делаем | обязательно | G2, G3, R1 |
| **Сколько нужно** | обязательно, по умолчанию `+1` | R3 («записалось восемь» — размер компании), M1 |
| Дата и время | опционально; появляется при подтверждении отклика | R3 (напоминание нужно к дате) |
| Место | опционально; публичное по умолчанию; точный адрес — только подтверждённым | R2 («не знаю, где мы будем»), E3 («могу уйти») |
| Описание | опционально | — |
| Категория / теги | опционально | G3 (фильтр по хобби) |
| **Кто может откликнуться** | `Anyone` · `Women only` · `Men only`, только свой пол | R2 |
| Автор | ссылка на профиль | S2 («не безымянное объявление») |
| Статус | открыт · компания собрана · встреча назначена · прошёл · погас | R3, R4 |
| Срок жизни | 14 дней без даты | — страховка, не job |
| Повторяется | да / нет → порождает серию | R4, G4 |
| Шаблон | из какого создан | R5 |

**Связи:** ← автор (человек) · → отклики · → участники (подтверждённые отклики) ·
→ чат запроса · → встреча (когда назначена дата) · → серия (если повторяется) ·
← шаблон.

**Чего у запроса нет по job:** лимита мест как у события (его заменяет «сколько нужно»),
роли организатора (R5 — «держалось не только на мне», не «я веду группу»), цены.

### 3. Отклик

**Порождает:** R1 — первый шаг к встрече; E2 «не чувствовать себя навязчивой» — отклик
на явный запрос не навязчив по определению; R2 — автор подтверждает, значит контролирует,
с кем идёт.

| Поле | Значения |
|---|---|
| Кто | профиль откликнувшегося |
| На что | запрос |
| Статус | ожидает · подтверждён автором · отклонён · отозван |
| Время | создания и решения |

**Связи:** ← человек · ← запрос · → чат (открывается после подтверждения) ·
→ участие во встрече.

**Асимметрия — часть сущности, а не экрана:** отклик не занимает место, пока автор
не подтвердил. Это единственный контакт без взаимного лайка.

---

### 4. Совпадение (матч)

**Порождает:** R1 «нашла человека с общими интересами и надо написать первой»;
E2 — взаимное согласие до контакта снимает навязчивость.

| Часть | Поля |
|---|---|
| Лайк | кто → кого, время; skip не хранится как сущность `[?]` |
| Совпадение | два профиля, число общих интересов, время |

**Связи:** ← два человека · → чат 1:1.

**Оговорка:** сама механика колоды — решение `D-10`, не требование job. Job R1 требует
«найти человека с общими интересами»; что находка происходит через взаимный лайк —
наш выбор. Сущность в списке потому, что E2 требует взаимного согласия до контакта.

---

### 5. Чат

**Порождает:** R4 «продолжить с теми же людьми без усилия первого раза» — чат хранит
контекст между встречами; R1 — но с оговоркой: job хочет **минимизировать** переписку
(«виделись, а не переписывались»).

| Поле | Значения |
|---|---|
| Тип | 1:1 (из совпадения) · запроса (`+1` — диалог, `+N` — групповой) · серии |
| Участники | профили |
| Привязка | совпадение · запрос · серия |
| Сообщения | текст, эмодзи, прочитано; медиа — нет |
| Ice-breaker | подсказки в пустом чате | 

**Связи:** ← совпадение или запрос · → участники · ← серия (один чат на серию).

**Чего у чата нет по job:** статуса присутствия собеседника — S1 требует отзывчивости,
не «онлайн».

---

### 6. Встреча

**Порождает:** R3 «не окажусь там одна»; R4 «встреча прошла хорошо и я хочу повторить»;
M1 «через несколько встреч»; E3 «могу уйти в любой момент».

`[?]` **Отдельная ли это сущность** — или состояние запроса «дата назначена».
По job она отдельна: у неё свои события (напоминание, явка, check-in), а у запроса без
даты их нет. В модели данных может оказаться тем же объектом.

| Поле | Из какого job |
|---|---|
| Запрос-источник | — |
| Дата и время | R3 (к чему напоминать) |
| Место: площадка, район, точный адрес — только участникам | R2, E3 |
| Состав: подтверждённые участники | R3 |
| Подтверждения явки | R3 |
| Факты присутствия | S1, R4, M1 |
| Приватная обратная связь | **ни одного job** — гигиена безопасности, раздел «Гигиена» `D-31` |

**Связи:** ← запрос · → участники · → подтверждения явки · → подтверждения присутствия ·
→ ссылка близкому · ← серия.

---

### 7. Подтверждение явки (`Still going?`)

**Порождает:** R3 напрямую — «записаться легко, а прийти нет».

| Поле | Значения |
|---|---|
| Участник | профиль |
| Встреча | ссылка |
| Ответ | `Yes` · `Can't make it` · нет ответа |
| Время | за сутки до встречи |

**Связи:** ← встреча · ← человек · → счётчик в ленте (двухфазный: `going` → `confirmed`).

**Часть сущности:** молчание — не отказ; `Can't make it` освобождает место, «нет ответа» — нет.

---

### 8. Подтверждение присутствия (`Who made it?`)

**Порождает:** S1 «выглядеть тем, кому можно доверять» — единственная история, которая
наполняется сама; R4 — история встреч с теми же людьми; M1 — «через несколько встреч».

| Поле | Значения |
|---|---|
| Кто отметил | профиль |
| Кого | профили участников |
| Встреча | ссылка |
| Окно | 14 дней |
| Режим | double-blind: кто кого отметил, не видит никто |

**Связи:** ← встреча · ← люди · → счётчик `meetups attended` на профиле · → метрика повтора.

**Часть сущности:** засчитано, если отметил хотя бы один другой участник. На паре
double-blind вырождается — это свойство сущности, а не экрана.

---

### 9. Серия (повторяющийся запрос)

**Порождает:** R4 «продолжить с теми же людьми без усилия первого раза»; R5 «в пятый раз
собираю ту же встречу»; G4 «вернуть не людей, а то, что мы делали».

| Поле | Значения |
|---|---|
| Базовый запрос | из чего возникла |
| Состав | переносится между встречами |
| Чат | один на серию |
| История встреч | список |
| Правило повтора | еженедельно `[?]` — интервал не задан |

**Связи:** ← запрос · → встречи · → чат · → участники.

**Часть сущности:** серию нельзя создать отдельно — она возникает из запроса, когда автор
отмечает «повторяется».

---

### 10. Верификация

**Порождает:** R2 «риск понятен до выхода из дома»; G5 «доказать, что я — это я».

| Поле | Значения |
|---|---|
| Статус | не начата · ожидает · пройдена · отказ · на ручной проверке |
| Причина отказа | лицо вне кадра · темно · поза не совпала |
| Попытки | без лимита |
| Результат | бейдж Verified на профиле |

**Связи:** ← человек · → бейдж Verified · → доступ к отклику и первому сообщению.

**Чего верификация не доказывает — часть сущности:** живое фото — да; личность, пол,
намерение — нет.

### 11. Жалоба и блокировка

**Порождает:** E3 «никто не удержит» — возможность выйти из контакта; R2.

| Поле | Значения |
|---|---|
| Кто → на кого | профили |
| Контекст | профиль · карточка · чат · запрос |
| Причина | harassment · fake profile · inappropriate photos · spam · underage · other |
| Комментарий | текст |
| Блокировка | мгновенная, взаимная; чат в архив |

**Связи:** ← два человека · → модерация `[?]` (бэкстейдж, в продукте не видна) ·
→ список заблокированных.

|---|---|

| Поле | Значения |
|---|---|
| Название | прогулка · настолки · пробежка · кофе · кино |
| Предзаполнение | занятие, категория, типовой размер |

**Связи:** → запрос.

### 14. Интерес (тег)

**Порождает:** R1 «общие интересы»; G3 «компания под конкретное хобби»; G1.

Справочная сущность: курируемый каталог — Sports, Music, Food, Games, Outdoors, Art,
Movies, Travel, Tech, Books. Связывает **человека ↔ запрос ↔ фильтр** — единственный
объект, через который совпадение считается.

**Связи:** ← профили · ← запросы · ← фильтры.

### 15. Фильтр

**Порождает:** G3 — фильтр ленты по категории; R2 — «Verified only».

Не хранимый объект, а параметры запроса к колоде и ленте:

| Где | Параметры | Из какого job |
|---|---|---|
| Колода | возраст, радиус, интересы, только верифицированные | R2 |
| Лента запросов | дата (только к датированным), расстояние, категория, размер компании | G3, R3 |

**Чего в фильтре нет по job:** пола. R2 закрывается ограничением на своём запросе,
а не фильтром чужих.

## Под вопросом

Есть в брифе, но ни один job из `jtbd.md` не требует. Не выброшены — но перед тем как
рисовать для них экран, нужен job или решение, что это гигиена.

| Объект | Откуда в брифе | Почему без job |
|---|---|---|
| **Интент** («Just moved here», «New hobby»…) | §6, `D-08` | Бриф сам назвал чипы «гигиеной категории, а не отстройкой». Срез плотности «ещё 12 переехали» служит обязательству §2.1, а не job человека. E1 «чувствовать, что это нормально» — ближайший, но связь не показана `[?]` |
| ~~Приватная обратная связь~~ | §7.5 | **Решено `D-31`:** гигиена безопасности, остаётся в MVP. Перенесена в раздел «Гигиена» ниже |
| ~~Настройки приватности~~ | §7.1 | **Решено `D-32`:** переключатели уходят из v1, инвариант остаётся. Сущности нет |
| **Цена запроса** (поле `Free`) | §9 | Зарезервировано под модель выручки, которая открыта заново `D-28`. Job у неё нет и не будет — это не про человека |
| **Настройки уведомлений** | §5.4 (следствие напоминания) | Напоминание порождает R3, настройки к нему — нет. Появились как «новая поверхность», не как потребность |
| **Предпочтения по компании** (возрастной диапазон, кого ищу) | §5.1 | Параметры подбора; job их не называет. Возможно, часть фильтра `[?]` |
| **Undo последнего свайпа** | §5.2 | В `jtbd.md` уже помечен кандидатом на вылет: удобство механики, не прогресс человека |
| **Модерация** | §7.4, §7.5 | Принимает жалобы и сигналы; для человека невидима. Сущность бэкстейджа, в продуктовую модель не входит `[?]` |

**Решено 2026-09-16.** Два объекта из этой таблицы разобраны, потому что оба стояли
в MVP: обратная связь — гигиена (`D-31`), переключатели приватности — вне v1 (`D-32`).
Остальные шесть ждут той же развилки: job, гигиена или вылет.

## Гигиена безопасности

Сущности, которые порождает **обязательство продукта**, а не job человека. Они в MVP,
но под них не выдумывается job — и экран под них рисуется как служебный, не как ценность.

### Г1. Приватная обратная связь (`Anything off?`) `D-31`

| Поле | Значения |
|---|---|
| Кто | профиль участника |
| Встреча | ссылка |
| Текст | свободный, необязательный |
| Адресат | только модерация; вторая сторона не узнаёт никогда |

**Связи:** ← встреча · ← человек · → модерация.

**Почему без job:** служит платформе — ранний сигнал до того, как ситуация станет
инцидентом. Если интервью (вопрос 8 в гайде) покажут, что человеку это нужно самому,
появится job и сущность переедет в основной список.

## Экраны

**Правила раздела.**

- Экраны выведены из сущностей и jobs, **не из структуры конкурентов**. Вкладок здесь нет —
  группировка по объектам и по тому, что человек пытается сделать.
- У каждого экрана в скобках — job со ссылкой на [`jtbd.md`](./research/jtbd.md).
  Нет job — **[СИРОТА]**.
- **Empty · loading · error · гейт — состояния экрана, не экраны.** Они стоят под экраном
  с пометкой `~`. Пустая колода — состояние колоды, хотя проектируется первой.
- Глубина — два уровня: объект → экран. Третий уровень появится на шаге 3 сознательно.
- Состояния, помеченные ЗАГЛАВНЫМИ, найдены при построении потоков
  ([`flows.md`](./flows.md), 2026-09-17) — их в инвентаризации не было.

**Обозначения.** `P` — нужен primary-персоне (Даша): среди jobs экрана есть её job по матрице.
`S` — только secondary (Максим · Оля · Артём). `А` — нужен Артёму как автору `+N`.
`~` — состояние. Job в скобках, ссылка ведёт на формулировку.

```
MeetMates
│
├── Человек
│   ├── Профиль другого человека                   (R2, G1, R1)          P
│   │     фото · интересы с подсветкой общих · сигналы доверия · ближайшие запросы
│   ├── Мой профиль — как меня видят               (S1)                  P
│   │     ~ счётчик встреч вырос
│   ├── Редактирование профиля                     (R1, S1, R2)          P
│   │     анкета · фото · интересы · пол
│   ├── Что поднимет уровень                       (S1)                  P
│   └── Верификация — селфи по позе                (R2, G5)              P
│         ~ захват · обработка · пройдена
│         ~ не распознали — причина, пересдать
│         ~ на ручной проверке
```

**Отклик** и **Серия** своих экранов не имеют: отклик — действие на карточке запроса,
«жду ответа» — её состояние; серия — строка в «Моих планах», история на карточке
и один чат.

**Почему нет вкладок.** Дерево выше — не навигация. Discover · Plans · Chats · Profile
из брифа §6 — это способ добраться до экранов, и его надо вывести на шаге 3 из того,
что человек делает чаще. Сейчас важно другое: у какого объекта какой экран и зачем.

## Навигация

Экраны — из раздела выше, нового дерева нет. Здесь решается только, **как до них добираться**:
что видно всегда, что появляется в потоке, что спрятано.

### 1. Глобальная навигация — три пункта

Каждый пункт — вход в кластер jobs, и у каждого названо, **какой job за ним стоит**.
Четвёртого пункта нет сознательно — объяснение ниже.

| Пункт | Экран за ним | Job-кластер | Почему это отдельный вход |
|---|---|---|---|
| **People** | Колода | R1 «начать с плана, а не с себя» — найти человека с общими интересами · G1 «решить быстро» | Единственный экран, где человек **выбирает людей**. Вход в продукт по `D-10` |
| **Plans** | Лента запросов · сегмент «Мои» | **M1** «у моих планов компания» · G2 «не отказываться от плана» · G3 · R4 (мои планы — продолжить) | **Детерминированный путь к main job.** Колода даёт совпадение по вероятности, запрос — по действию |
| **Chats** | Список чатов | R4 «продолжить с теми же людьми» — контекст между встречами · R1 — первое сообщение как приглашение | Единственное место, где **уже найденные** люди. После первой встречи это главный экран |

**Почему не четыре.** В брифе §6 стоит четвёртая вкладка — Profile. Job за ней есть:
S1 «выглядеть тем, кому можно доверять», верификация (R2, G5), «что поднимет уровень».
Но это **редкие действия**: профиль правят раз в неделю, верификацию проходят один раз,
ступень смотрят иногда. Вкладка на постоянной панели нужна тому, что делают **каждый день**,
а Profile попал бы туда потому, что так у всех. Он уходит в **глубокий слой** — за аватар
в шапке любого глобального экрана, один тап отовсюду.

> Это расходится с §6 брифа (четыре вкладки). Если модель принимается — нужен `D-33`
> и правка §6. Если нет — четвёртая вкладка возвращается, глубина main job не меняется.

**Что ещё не попало в глобальное — и почему:**

- **«+» создать запрос** — не плавающая кнопка на всех экранах, а кнопка в шапке Plans
  и **в каждом пустом состоянии** (обязательство §2.1, п. 3). Она про один объект,
  ей место рядом с ним.
- **Мои планы** — сегмент внутри Plans (Лента · Мои), не отдельный пункт: это тот же
  объект с другой стороны.
- **Уведомления** — не пункт и не экран: напоминание и check-in приходят пушем
  и открывают свой экран напрямую.

### 2. Глубина до main job

**Main job:** собрать в новом городе двух-трёх людей, с кем можно куда-то пойти без повода.
**Primary-персона:** Даша, переехала.

**Что считаем.** Целиком job закрывается неделями — двумя-тремя состоявшимися встречами
и повтором, — и тапами не меряется; его меряет метрика повтора (§11). Тапами меряется
**первое действие, которое двигает M1**: откликнуться на чей-то план или опубликовать свой.
Первый экран после онбординга — колода (`D-10`). На старте она **пустая** (`D-22`):
считаем от неё, потому что реальная Даша увидит именно её.

| Путь | Тапы | |
|---|---|---|
| **Откликнуться на чужой план** | Колода (пустая) → `Plans` **1** → карточка запроса **2** → `Ask to join` **3** | **3** |
| **Опубликовать свой** | Колода → `Plans` **1** → `+` **2** → заполнить одно поле и `Post` **3** | **3** *+ ввод* |
| Через человека | Колода → карточка **1** → профиль → его запрос **2** → `Ask to join` **3** | **3**, только если у человека есть запрос |
| Через совпадение | Свайп → совпадение → `Say hi` → сообщение | не считается: совпадение — вероятность, не действие |

**Глубина — 3. Ровно на границе, перестраивать не нужно.**

**Компромисс, который эту тройку даёт.** Один тап из трёх — цена `D-10`: первый экран
колода, а не лента. Если бы продукт открывался планами, путь был бы **2**
(лента → карточка → отклик). Решение принято с этой ценой сознательно, и вот что её гасит:

- **пустая колода ведёт в планы одним тапом** — не «нет людей», а «посмотреть планы рядом»;
- **выход в планы есть на колоде всегда**, не только в пустом состоянии (§4);
- сама `Plans` — глобальная, а не спрятанная за профилем: путь через человека тоже 3,
  но он работает, только если у человека есть запрос.

**Что было бы 4 и почему этого не будет:** Plans внутри Profile, или «Мои планы» отдельной
вкладкой с лентой внутри, или карточка запроса за двумя экранами — любой из вариантов даёт 4.
Именно поэтому Plans в глобальной панели, а Profile — нет.

**Онбординг не считается:** это один раз. Но записано, сколько там шагов до первой колоды —
семь экранов, из них три пропускаемые (интент, геолокация, верификация).

### 3. Три слоя

**Глобальное — видно всегда.**
Нижняя панель `People · Plans · Chats` · аватар в шапке (вход в глубокий слой) ·
на `Plans` — кнопка `+`.

**Контекстное — появляется в потоке, когда есть объект.**

| Появляется | Откуда |
|---|---|
| Создание запроса | `+` в шапке Plans и в каждом пустом состоянии |
| Фильтры колоды · фильтры ленты | Иконка на колоде / ленте → bottom sheet |
| Карточка запроса | Из ленты, из профиля человека, из чата, из пуша |
| Совпадение | Модальный момент после взаимного лайка |
| Диалог | Из списка чатов, из совпадения, из подтверждённого отклика |
| Гейт верификации | Внутри диалога и на `Ask to join`, когда не верифицирован |
| Отклики на мой запрос | С карточки своего запроса; бейдж на `Plans → Мои` |
| Напоминание `Still going?` | Пуш за сутки → свой экран |
| Кто дошёл `Who made it?` | Пуш после встречи → свой экран |
| Приватная обратная связь | Последний шаг после `Who made it?` |
| Ссылка близкому | С карточки встречи, когда дата назначена |
| Жалоба · блокировка | Меню `⋯` на любом экране, где виден другой человек |
| Расширение радиуса | Карточка-разделитель внутри колоды |

**Глубокое — редкие действия, за аватаром.**

| Экран | Тапов от любого глобального |
|---|---|
| Мой профиль | 1 |
| Редактирование · что поднимет уровень · верификация | 2 |
| Настройки · геолокация · заблокированные · safety center | 2 |

Верификация — в двух слоях сразу: глубоко (по своей воле) и контекстно (гейт в момент
максимальной мотивации, `D-03`). Второй вход важнее первого.

**Одноразовое — онбординг, до первого глобального экрана.**
Splash → регистрация / вход → возрастной гейт → настройка профиля → выбор интересов →
интент → разрешение геолокации → верификация → колода. Семь экранов, три пропускаемые.
В слои не входит: после первого прохода к ним не возвращаются, а профиль и верификация
дальше живут в глубоком слое.
