# Паттерны

Компонент — один кирпич: кнопка, карточка, поле. **Паттерн — кладка, которая повторяется:**
шапка экрана, лента карточек, пустое состояние с выходом.

**Порог — три экрана.** Композиция, которой нет на трёх экранах, здесь не заводится:
это частный случай, а не паттерн. Появится третий экран — заведём тогда. У инвентаря
компонентов порог два экрана ([`ui/inventory.md`](../../ui/inventory.md)), у паттерна выше:
кладка повторяется реже кирпича, и случайное совпадение двух экранов легче принять
за правило.

## Что лежит в файле

Один файл на паттерн, и в нём только разметка из классов кита плюс шапка-комментарий:

| Поле | Что значит |
|---|---|
| **Паттерн** | Имя — по роли, а не по экрану |
| **Экраны** | Где он уже стоит. Меньше трёх — файла здесь не будет |
| **Из чего** | Ядро: компоненты, которые есть на **всех** названных экранах |
| **Варианты** | То, что встречается не везде: вторая кнопка, миниатюра, время |
| **Когда брать** · **Когда не брать** | Граница с соседним решением |

**Своих стилей у паттерна нет.** Ни `<style>`, ни `style="..."`, ни классов, которых
не было бы в [`../components/`](../components/). Паттерн говорит о составе и порядке —
всё остальное уже сказано компонентами.

## Что проверяет сборка

`node scripts/build-docs.mjs` роняется, если:

1. названо меньше трёх экранов;
2. названного экрана нет среди `concept/screens/`;
3. в разметке есть класс, которого нет в ките;
4. у паттерна свои стили;
5. **ядро стоит не на всех названных экранах** — значит это вариант, а не ядро.

Пятая проверка и есть защита от выдуманных паттернов: сказать «так везде» и не показать
где — не получится.
