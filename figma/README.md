# Токены в Figma

Два файла, оба собираются из корневого [`tokens.css`](../tokens.css)
скриптом `node scripts/build-figma-tokens.mjs`. **Руками их не правят** —
правят `tokens.css` и пересобирают, иначе Figma и продукт разойдутся.

| Файл | Что это | Когда брать |
|---|---|---|
| [`tokens.json`](./tokens.json) | Набор для плагина **Tokens Studio**: два слоя, `primitive` и `semantic`; роль ссылается на примитив ссылкой вида `{primitive.color.plum-900}` | Если в файле уже живёт Tokens Studio или нужен обмен с разработкой |
| [`import-from-url.js`](./import-from-url.js) | **48 строк** для плагина-консоли: забирает набор по ссылке и создаёт переменные | Обычный случай: быстро и нечего копировать |
| [`import-variables.js`](./import-variables.js) | То же самое, но со всеми значениями внутри — 845 строк | Если файл закрыт для сети или нужен автономный прогон |
| [`variables.json`](./variables.json) | Машинный набор, который читает короткий скрипт | Сам по себе не нужен |

Внутри: **92 примитива** и **28 семантических ролей**; двадцать из них стоят
ссылками на примитив, остальные восемь — составные рецепты (тени, кольца, блик
заглушки), и они переносятся строками: Figma не держит переменной ни тень,
ни градиент.

## Путь 0 — короткий: 48 строк в Scripter

Самый быстрый способ: вставить [`import-from-url.js`](./import-from-url.js) —
он сам забирает [`variables.json`](./variables.json) по ссылке и раскладывает
переменные. Вставлять нужно сорок восемь строк, а не тысячу.

Требует только, чтобы файл `variables.json` лежал в публичной ветке —
он там и лежит.

## Путь 1 — переменные Figma без сети

1. Открыть нужный файл в Figma.
2. `Plugins → Scripter` (бесплатный плагин-консоль; подойдёт любой плагин,
   умеющий выполнить код в файле).
3. Вставить содержимое [`import-variables.js`](./import-variables.js) и нажать **Run**.
4. Внизу появится уведомление со счётом: сколько примитивов, ролей и ссылок
   перенесено. Коллекции встанут в `Local variables`: **Primitive** и **Semantic**.

Повторный запуск не плодит дубли: переменные с теми же именами обновляются.
У каждой переменной в описании стоит имя из CSS (`--text-primary → --plum-900`),
чтобы связь с кодом читалась прямо в Figma.

## Путь 2 — Tokens Studio

1. `Plugins → Tokens Studio for Figma`.
2. `Tools → Load from file/folder` → выбрать [`tokens.json`](./tokens.json).
3. В списке наборов включить оба: `primitive` и `semantic`.
4. `Apply to document` — токены станут переменными или стилями, в зависимости
   от настроек плагина.

## Что переносится не полностью

| Что | Почему |
|---|---|
| **Тени** (`--shadow-1…3`, `--ring-*`) | Figma держит переменными цвет, число и строку, но не тень. Скрипт заводит для них **стили эффектов** с правильными именами и описанием; сами значения в Figma нужно один раз выставить руками — это шесть стилей |
| **Размытие экрана** (`--gradient-page-wash`) | Градиент из трёх слоёв переменной не бывает. В Figma это заливка-стиль; значение лежит в описании |
| **Шрифт** (`--font-sans`) и **кривая движения** (`--ease-out`) | Переносятся строками: Figma их не применяет сама, но значение видно и не разойдётся с кодом |
| **Проценты** (`--width-s/m/l`, `--width-bubble`) | Остаются строками: в Figma число без единицы измерения смысла не имеет |

## Чего в наборе нет нарочно

**Тёмной темы.** Блок `[data-theme="dark"]` в `tokens.css` переопределяет те же
девятнадцать имён другими значениями, и в наборе без режимов они просто затёрли бы
светлые. Тема в продукт не принята (`D-76`): примут — поедет **вторым режимом
коллекции Semantic**, а не вторым набором имён.
